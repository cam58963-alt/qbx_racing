# CAM Racing（qbx_racing）

Qbox（qbx_core）サーバー向けのレーススクリプトです。
コースはゲーム内で作れます。遊び方は、ソロのタイムアタック、毎日のデイリーレース、複数人でのマルチプレイ（賞金あり／なし）、ランキングです。

- バージョン：4.2.0
- メニュー：`/race`（タブレット連携にも対応）
- 画面の文言はすべて日本語です

---

## 主な機能

| 機能 | 内容 |
| --- | --- |
| コース作成 | ゲーム内で走りながらチェックポイントと曲がり角ガイドを置きます。車・ヘリ・ボート、周回・スプリントに対応し、チェックポイントは最大500個まで置けます |
| タイムアタック | 最初のゴール記録から目標タイムを自動で決めます。目標タイム以内でゴールすると、1人1レース1回だけ報酬をもらえます |
| デイリーレース | 毎日サーバー共通で1〜2レースを選びます。完走で報酬の1/3、目標タイム達成で残りの2/3をもらえます（それぞれ1日1回） |
| マルチプレイ | セッションを作ってみんなで走ります。参加費・賞金・主催者スポンサーを付けた掛けレースもできます |
| ランキング | 完走・目標達成・リタイアでポイントが増減します。マルチでは参加者同士でポイントをやり取りします |
| ゴーストモード | レースごとに「プレイヤーのみ」か「フル（NPCの車もすり抜け）」を選べます |
| 自作マーカー | 画像のチェックポイント、4つ先までの予告、ルート線、曲がり角の矢印を表示します |
| 不正対策 | 通過の順番・位置・速度・瞬間移動・乗り換えをサーバーで確認します |

## 必要なもの

- [qbx_core](https://github.com/Qbox-project/qbx_core)
- [ox_lib](https://github.com/overextended/ox_lib)
- [oxmysql](https://github.com/overextended/oxmysql)
- MySQL / MariaDB
- OneSync（サーバー側で位置・車両を確認するため）
- （任意）`cam_tablet`：タブレットのアプリとして開く場合
- （任意）`qb-management`：掛けレースの手数料を会社口座に入れる場合

## インストール

1. `qbx_racing` フォルダを `resources` に置きます。
2. `server.cfg` に追加します。依存リソースより後に起動してください。
   ```cfg
   ensure ox_lib
   ensure oxmysql
   ensure qbx_core
   ensure qbx_racing
   ```
3. サーバーを起動します。
   - 足りないテーブルや列は起動時に自動で作られます。
   - 手動で作る場合は `qbx_racing/sql/install.sql` を実行してください。何度実行しても大丈夫です。
4. `config.lua` の `Config.RaceManagerJobs` に、コースを作れるジョブを設定します。

更新するときはファイルを入れ替えて `ensure qbx_racing`（またはサーバー再起動）するだけです。新しい列は起動時に追加されます。

## 使い方

### はじめに
1. `/race` でメニューを開きます。
2. 初回はドライバーネームを登録します（英数字と `_`、3〜20文字）。

### メニューのタブ
| タブ | 内容 |
| --- | --- |
| ホーム | プロフィール、ポイント、今日のデイリーレース |
| レース一覧 | 全レース。車両タイプで絞り込めます。詳細からソロ出走・マルチセッション作成・セッション参加ができます |
| タイムアタック | 目標タイム・報酬・受け取り済みかどうか。目標タイムが決まるまでは「計測中」と表示します |
| ランキング | ポイント順のランキングとポイントのルール |
| 管理 | コース作成、デイリーの選び直し、目標タイムのリセット（`RaceManagerJobs` のジョブだけに表示） |

### レースを走る（ソロ）
1. レースを選ぶと、スタート地点にウェイポイントが付きます。
2. 対象の車両でスタート地点に着くと、カウントダウンが始まります。
   - **準備 10秒**：車両はまだ動かせます。コースのマーカーを見て向きを直してください。
   - **ロック 3秒**：車両が止まり、終わるとスタートします。
   - 準備中にスタート地点から離れたり車を降りたりした場合は、ロック開始時に元の位置・元の車両に戻されます。
3. チェックポイントを順番に通ってゴールします。
4. 途中でやめるときは `/race` を開き、「レースをキャンセル」を押します。

### コースを作る（管理者）
1. 「管理」タブで「新規レース作成」を押します。
2. 次の項目を入力します。
   - 名前
   - 説明
   - 車両タイプ（車・ヘリ・ボート）
   - レースタイプ（周回・スプリント）
   - 周回数
   - ゴーストモード
3. 走りながら、次のキーで置いていきます。

| キー | 操作 |
| --- | --- |
| `E` | 今いる場所にチェックポイントを置く |
| `Backspace` | 最後のチェックポイントを消す |
| `←` / `→` | 今いる場所に曲がり角ガイド（左・右）を置く |
| `↑` / `↓` | 最後のガイドを横に長く・短くする |
| `Delete` | 最後のガイドを消す |
| `R` | 作成完了（3個以上必要） |
| `ESC` | 作成をやめる |

- 曲がり角ガイドは、一番近いチェックポイントに向かっている間に表示されます。手動で置かない場合は、コースの角度から自動で表示します。
- 作成中は、近くのチェックポイント（30個）とガイドだけを表示します。全部描くと表示できるマーカーの上限を超えて消えてしまうためです。

### マルチプレイ
1. レース詳細の「マルチセッション作成」からセッションを作ります。
   - 準備時間（5〜30秒）を決めます。
   - 掛けレースにする場合は参加費とスポンサー額も決めます。掛けレースは `Config.BetRaceJobs` のジョブだけ作れます。
2. 参加者は同じレースの詳細から「セッション参加」を押して参加します。ロビーを閉じてしまったら `/racelobby` で開き直せます。
3. 全員が対象の車両でスタート地点（半径30m以内）に集まったら、主催者が「レース開始」を押します。
4. 準備カウント（ロックなし）→ロック3秒のあとにスタートします。
5. 掛けレースの賞金は1位50%・2位30%・3位20%です。セッションが中止された場合、参加費とスポンサー金は返金されます。

### タイムアタック
- レース作成後、10回のゴール（3人以上）がそろうと目標タイムが決まります。
  - 目標タイムは、各ドライバーのベストタイムの平均です。
  - 極端に遅いベストは平均から除きます。
- 報酬はコースの長さ、チェックポイントの密度、目標タイム、低速ボーナス（細道やカーブが多いほど加算）から自動で計算します。
- 報酬は100万〜1500万で、1人1レース1回だけもらえます。

### デイリーレース
- 毎日サーバー共通で、目標タイムが決まっているレースから1〜2個を選びます。
- 完走で報酬の1/3、目標タイム以内で残りの2/3をもらえます。
- 両方受け取ったレースは、その日はデイリーとして出走できません。

### ランキング
| 結果 | ポイント |
| --- | --- |
| 初期ポイント | 1000 |
| ソロで完走（同じレースは1日1回） | +5 |
| ソロで目標タイム以内（同じレースは1日1回） | +10 |
| ソロでリタイア | -5 |
| マルチ | 自分より下の順位の参加者1人につき、その人から5ポイントもらう |

## 主な設定（`config.lua`）

| 設定 | 内容 |
| --- | --- |
| `Config.VehicleTypes.*` | 車両タイプごとの設定です。<br>・使える車両クラス<br>・チェックポイントの見た目<br>・通過判定の余裕（`progressDistanceMargin`）<br>・不正対策の最高速度（`maxSpeed`：車300・航空機450・船200 km/h） |
| `Config.Checkpoint` | チェックポイントの数（最低3・最大500）と自作マーカーの設定です。<br>・`customMarker.enabled = false` で標準のチェックポイント表示に戻ります<br>・`turnGuide.showAhead = false` で、先のチェックポイントの曲がり角ガイドを表示しなくなります<br>・`creationDraw` は作成中に表示する数です |
| `Config.Race` | ・`prepSeconds`：準備カウント<br>・`lockSeconds`：ロックカウント<br>・`vehicleSwapCheck`：乗り換えチェック<br>・`betting`：掛けレース |
| `Config.TimeAttack` | 目標タイムを決める条件と報酬の計算 |
| `Config.Daily` | デイリーのレース数・報酬倍率・完走でもらえる割合 |
| `Config.Ranking` | ランキングのポイント |
| `Config.Multiplayer` | ・人数<br>・準備時間<br>・制限時間<br>・ゴーストモード<br>・スタート地点の範囲（`countdownRestrictions.startAreaRadius`） |
| `Config.UI` | ・コマンド<br>・キーバインド<br>・表示モード（`standalone` / `tablet`）<br>・コース作成のキー |
| `Config.Security.antiCheat` | 瞬間移動の判定（`teleportThreshold`）などの不正対策 |

### 自作マーカーの画像
- 画像は `qbx_racing/html/img/markers/` にあります（PNG）。
- 同じ名前で置き換えると見た目を変えられます。
- ヘリ用の画像は `heli_` が付いたファイルです。
- 画像を追加したら `fxmanifest.lua` の `files` にも登録してください（`html/img/markers/*.png` は登録済み）。

## タブレット連携（任意）

`Config.UI.mode = 'tablet'` にすると、`cam_tablet` のアプリとして登録されます。

- 登録内容は `Config.UI.tablet.app` で設定します。
- `/race` はアプリを開くショートカットになります。
- タブレットのリソースが起動していない場合は、今までどおり全画面メニューで動きます。
- レース中のHUDは、どちらのモードでも画面に表示されます。

---

## 不正対策について

記録や報酬に関わる確認はサーバーで行います。

- チェックポイントは順番にしか進めません。通過の報告はサーバーで見た位置から確認します。
- ゴールタイムはサーバーで測った経過時間と比べます。その乗り物で物理的に出せない速さのゴールは記録しません。
  - 上手い人が大幅に速くても、出せる速さであれば記録されます。
- 走行中の移動距離を定期的に確認し、瞬間移動した走りは記録しません。
- スタート時の車両以外で走った場合はリタイアになります。

普通に走ってもリタイアになったり記録されなかったりする場合は、次の値を少し大きくしてください。
- `Config.VehicleTypes.*.progressDistanceMargin`
- `Config.Security.antiCheat.teleportThreshold`

## 困ったとき

| 症状 | 確認すること |
| --- | --- |
| マーカーが表示されない | `customMarker.enabled` を確認します。画像がない場合は標準のチェックポイントで表示されます |
| 作成中にマーカーが消える | `Checkpoint.creationDraw` の数を減らします |
| 普通に走ってもリタイアになる | 上の「不正対策について」の値を大きくします |
| 目標タイムが決まらない | 10回のゴールと3人以上のドライバーが必要です。管理タブから目標タイムをリセットすると、数え直しになります |
| マルチでレースを開始できない | 全員が対象の車両に乗り、スタート地点の半径30m以内にいるか確認します |
| デバッグログを見たい | `server.cfg` に `setr qbx_racing_debug true` を追加します |
